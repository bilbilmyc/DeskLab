# 本机体检与诊断导出

打开 DeskLab 页面后自动检查本机运行条件，工作区顶部显示摘要。点击“查看体检”，或打开“本机设置 → 运行与存储 → 本机体检”，可查看结果、处理建议和检查时间。

“重新检测”会重新读取当前状态；并发请求合并，五秒内的重复检测复用结果。自动检测可复用一分钟内的结果。修改 QEMU、运行模式或 ISO 目录后自动更新。体检不占用虚拟机操作队列，不阻止创建或启动；通过体检也不等于所有客体都能成功启动。

## 检查范围

- Windows x64 宿主、固件虚拟化和 WHPX。WHPX 通过 [Windows Hypervisor Platform API](https://learn.microsoft.com/en-us/virtualization/api/hypervisor-platform/funcs/whvgetcapability) 查询；权限不足、调用失败或超时时显示“未确认”，不会视为通过。
- QEMU 和 qemu-img 的实际版本命令能否执行、QEMU 是否支持所选加速模式，以及 UEFI 固件文件是否存在。TCG 模式下，硬件虚拟化未启用仅作提醒。
- 数据与 ISO 目录所在磁盘空间。低于 1 GiB 标记需处理、低于 10 GiB 提醒；这些是通用阈值，不代表安装所需空间。
- 目录写入：创建唯一的 `.desklab-check-*.tmp`，写入固定测试文本后关闭并删除，不改动已有文件。清理失败也会显示需处理。
- 当前可用内存、管理端口是否自动回退、能否分配并释放临时 TCP 回环端口。具体 SSH / TCP / UDP 映射仍由创建和启动流程验证。

体检不修改 Windows 功能、不提权、不启动虚拟机，也不会连接外部 Docker 或下载组件。开启虚拟化或 Windows 功能后，需要按系统要求重启再检查。

## 导出内容与边界

点击“导出诊断日志”，浏览器下载 JSON 文件到本机。导出前更新体检结果（五秒内结果可复用），不上传任何信息。

文件包含 DeskLab 版本、导出时间、检查结果，以及本次服务运行期间最近 100 条受支持操作的时间、固定操作名、状态和错误类别。目前记录环境创建、启停、重置、删除、保存模板、网络设置、模板导入、设置保存、内置 Docker 引擎操作和退出请求。`accepted` 表示后台任务已受理，不代表最终完成。操作记录保存在内存，退出后清空。

导出使用字段白名单，不收集原始启动日志、QEMU/容器输出、路径、实例名称、实例 ID、请求参数、环境变量、SSH 私钥、证书或令牌。因此能帮助定位问题类别，但不能代替完整错误现场。服务无法启动、页面无法打开时，仍需查看原有 `logs/startup.log`；此原始文件可能含本地路径，不包含在自动导出内。

## 开发验证

`bun test tests/diagnostics.test.ts` 验证状态判定、目录写入清理、并发与缓存、字段白名单、接口授权和数据保留。完整回归使用 `bun test tests`。

构建 EXE 后，可运行 `python scripts/checks/diagnostics-ui.py`。此检查需要开发环境安装 Python Playwright 和 Microsoft Edge，仅用于测试，不是成品运行依赖。脚本在 `.runtime/checks/diagnostics-ui-*` 中创建隔离数据，验证四种窗口宽度、键盘操作、自动重检、失败提示和 JSON 下载；结果与截图保存在同一目录，结束后退出测试程序。
