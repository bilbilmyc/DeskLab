# 发布与镜像加载

> v1.0.0 正式版为 Windows x64 基础安装包，`master` 为开发集成主线。完整包另外包含独立 Docker 的预装 Linux、CLI 和 Compose，见 [构建与 CI](build-and-ci.md)。以下“客体 ISO/模板磁盘”不包括专用 Docker 组件。

## Windows 成品

面向首次使用的成品是 **`DeskLab-Setup.exe`**。双击后选择安装目录，安装器会放好程序、创建数据和 ISO 目录，并提供快捷方式。无需复制开发项目的 `.data`，也不需要源码、Bun、Node.js 或 Docker。

安装后的 `DeskLab.exe` 内含网页、Bun 服务、系统目录、小型自动安装配方、ISO 下载清单、QEMU、DLL 和固件；打开后通过浏览器操作本机虚拟机。`desklab.install.json` 将安装版的数据目录固定在程序同级 `data/`。同级 `templates/README.txt` 提供模板说明，`builtin-catalogue.json` 仅供查看内置目录；实际系统模板通过程序管理，磁盘保存在 `data/templates/`。

首次启动时，程序将内置引擎释放到数据目录的 `runtime/<版本标识>/qemu`，之后复用。用户无需单独准备 `runtime` 文件夹。大型 ISO、已安装的操作系统和虚拟机数据不编入 EXE，因此升级程序不需要重新分发所有镜像。

## 系统自带与我的模板

「创建环境」和「模板库」都分为「系统自带」与「我的模板」。前者用于快速创建；模板库以卡片展示系统，点击「详情」在独立窗口中查看登录说明和管理模板。

系统自带的 8 套系统目录与默认配置编入程序。其中 **Ubuntu Server、Debian Server、Rocky Server、Windows 10、Windows Server** 带有首次自动安装配方；其余三套 Linux 桌面模板使用已有的已安装磁盘或手动安装。小型配方可以随程序升级，原版 ISO 和安装后的系统磁盘独立保留。

模板已经准备好时，在「创建环境」选择模板，点击「下一步」、填写环境名称，再点击「创建并启动」即可。程序从模板创建独立环境，使用模板建议的资源和启动方式，不需要再次提供 ISO。同一数据目录内已准备的磁盘可继续复用，不必重新安装。

两种安装包都不附带客体 ISO 或用户虚拟机模板磁盘。支持自动安装的模板显示「支持自动安装」，可点击「选择 ISO 并安装」；检测到对应 ISO 时显示「自动安装系统」。选择与模板版本对应的原版 ISO，填写名称，点击「创建并自动安装」。程序在新建虚拟磁盘中安装、配置默认账号和自动登录；收到完成报告并确认客体正常关机后，另外保存基础系统，再从本环境的磁盘启动。以后创建同类环境使用基于该基础系统的独立差分磁盘，无需重复安装。

自动安装后的账号是 Linux `root / DeskLab0987`、Windows `Administrator / DeskLab0987`。安装期间请保持 DeskLab 运行；强制中断可能需要重新创建环境。原版 ISO 不会被修改，安装配方作为独立配置介质提供给虚拟机。

已有配套已安装磁盘时，在对应卡片点击「详情 → 导入已安装的系统磁盘」即可选择资源。当前没有托管这些模板磁盘的在线下载服务；下载安装盘后仍需完成首次安装。需要离线使用时，可以提前准备对应原版 ISO，或携带完整的已准备数据目录。不能把原版 ISO 当作已经安装好的系统磁盘。

系统自带模板不能直接编辑或删除。想修改其中的软件或系统配置，应先创建环境，完成配置并正常关机，再选择「保存为模板」。填写名称即可保存；说明、默认 CPU / 内存和登录说明可按需要调整。保存后，它会出现在「我的模板」。

我的模板卡片的「详情」窗口提供「编辑模板信息」和「删除这个模板」。编辑默认资源只影响之后创建的环境，编辑登录说明不会修改系统里的账号或密码。要变更软件、密码或系统设置，仍需从模板创建环境，在系统内完成修改后另存为模板。

## 导入磁盘或从 ISO 安装

这两个入口适合使用自己的系统：

1. **已安装的虚拟磁盘**：在「模板库」选择「导入磁盘镜像」，通过「选择文件」选取 qcow2、raw、img、vmdk、vhdx 或 vdi，设置系统类型和原系统的 BIOS / UEFI 启动方式。DeskLab 将其转换并复制进我的模板，原文件保持不变。导入前应关闭原虚拟机；UEFI 镜像需包含默认 EFI 启动文件，不会导入其他软件的 NVRAM。
2. **新的安装盘**：在「创建环境」点击「已有 ISO 安装盘？从 ISO 安装」，再点击「下一步」。通过「选择文件」选取 ISO，也可输入绝对路径。窗口提示已匹配自动安装模板时，点击「创建并自动安装」；其他 ISO 填写名称后点击「开始安装」，按照原系统安装向导操作。也可从模板库底部的「从 ISO 安装」进入。ISO 直接引用原位置，安装期间应保留该文件。手动安装完成后正常关机，再保存为模板；保存成功会卸下原环境的安装盘，以后从系统磁盘启动，也可从「我的模板」创建新环境。

原版 ISO 只包含安装介质。支持的五套系统由内置配方完成登录配置；其他 ISO 需要自行设置账号密码，不会自动获得系统自带模板的默认账号。即使已有该系统的已准备模板，选择从 ISO 安装仍是一次新的安装。首次自动安装最直接的入口是「系统自带」中的对应系统，那里也可以选择未放在默认目录中的原版 ISO。

## ISO 目录与在线下载

「本机设置」分为「系统镜像」和「运行与存储」。在「系统镜像 → ISO 存放目录」卡片中点击「选择文件夹」，设置「ISO 目录」，再点击「保存并扫描」。如果没有修改路径，点击「重新扫描」即可检测新放入的文件。设置立即生效，无需重新启动 DeskLab。「运行与存储」中的「运行环境」「本地存储」「首次使用帮助」卡片分别提供引擎设置、实际文件位置和使用说明。

目录中已有对应完整大小的 ISO 时，安装盘卡片显示「已在本地」，点击「启动安装」进入创建流程。缺少 ISO 时，点击「在线下载」，程序会下载到选定目录。卡片上的「文件与来源」会打开独立窗口，展示文件名、本地位置和完整性说明。其他文件名的 ISO 也会显示在「目录中发现的其他 ISO」，由用户确认其内容和完整性后启动安装。扫描只读取文件名与大小，不为已有本地文件执行整盘 SHA256 校验；首次自动安装会另外检查所选原版 ISO 的大小与发布方 SHA256，Windows Server 没有公开官方哈希，只匹配大小并记录本地 SHA256。

在线下载显示进度条、已下载大小、总大小、速度和预计剩余时间。可以离开设置页面继续使用其他功能，任务仍在后台运行。下载可暂停、继续；失败时保留错误原因和重试入口。退出 DeskLab 会暂停任务，再次启动后手动点击「继续下载」。只有服务器提供可用的强 ETag 且正确响应 Range 请求时才接续原文件；缺少可靠续传信息时会从头下载，避免把不同内容拼接在一起。

更换 ISO 目录前，应先暂停所有下载中、校验中和排队的任务。目录设置不会迁移文件，也不会改写已创建环境保存的 ISO 路径。旧目录中的暂停任务和临时文件会保留；重新选择旧目录后可查看并继续。

目录选择优先级如下：

1. 「本机设置」保存的 `settings.isoDirectory`。
2. 未指定时，EXE 旁已有的 `iso/` 目录。
3. EXE 旁没有 `iso/` 时，数据目录下的 `iso/`。

在设置中清空路径并点击「保存并扫描」可恢复默认目录。目录需可访问且可写；手动填写的目录不存在时，程序会尝试创建。已准备好的系统模板独立于 ISO 存在，移走安装盘不会移走系统模板。

下载任务与未完成文件位于所选 ISO 目录中的 `.desklab-downloads/`；任务恢复不依赖原开发用 PowerShell 下载脚本。通过检查后才把文件发布为可用的 `.iso`。7 个镜像对照发布方 SHA256；Windows Server 2022 没有找到公开官方哈希，只检查完整字节数并记录本地 SHA256，不显示为通过官方哈希校验。固定版本地址、校验依据和本次检查见 [ISO 下载源核验](iso-sources.md)。

下载得到的是原版安装盘，不是已安装的系统磁盘。没有缓存时，支持的系统需要先自动安装一次，其他 ISO 由用户手动安装。当前支持 ISO 在线下载，尚未托管已安装模板磁盘。测试环境页面只有环境列表滚动，导航、标题、资源统计和筛选栏保持固定。

## 数据位置与移动

通过安装器选择目录后，布局如下：

```text
所选安装目录/
  DeskLab.exe
  desklab.install.json     固定使用同级 data/ 的安装标记
  iso/                    初始为空；安装盘存放目录，可在设置中更改
    .desklab-downloads/   下载任务与未完成文件
  templates/
    README.txt            模板使用说明
    builtin-catalogue.json 内置目录参考，不存放系统磁盘
  data/
    desklab.sqlite        配置、模板、环境、Docker 与端口映射元数据
    lab.json              SQLite 迁移标记
    backups/              升级前的 JSON 备份
    templates/            自动安装后缓存、导入或保存的系统磁盘
    machines/             各环境的可写磁盘及安装过程文件
    runtime/              首次运行自动释放的内置引擎
```

旧便携版和当前开发项目仍兼容已有布局：

```text
DeskLab/
  DeskLab.exe
  iso/                    默认安装盘与旧版配对清单，可在设置中更改
    .desklab-downloads/   下载任务与未完成文件
  .data/
    desklab.sqlite
    lab.json              迁移标记（首次升级前是旧数据）
    templates/
    machines/
    runtime/
```

数据位置优先使用 `LAB_DATA_DIR`；未设置时，带 `desklab.install.json` 的安装版使用同级 `data/`。没有安装标记的便携版若发现 EXE 旁存在 `.data/lab.json`，继续使用 `.data/`；否则使用 `%LOCALAPPDATA%\DeskLab\data`。安装标记不会自动迁移旧 `.data`；继续使用旧便携数据时，保留原布局并替换 EXE 即可。Bun 源码运行默认使用项目 `.data`。`dist/app/DeskLab.exe` 是开发构建副本，在本项目中通过 `desklab.bundle.json` 识别项目根目录。

要带走全部系统模板和测试环境，应先关闭所有环境和 DeskLab，再复制完整安装目录，保留 `DeskLab.exe`、`desklab.install.json` 和 `data/`；旧便携版则复制 EXE 与完整 `.data/`。想同时保留安装盘时，再复制实际选择的 ISO 目录，包括要保留的 `.desklab-downloads/`。模板与克隆磁盘之间使用相对路径；不要只复制单个差分磁盘，也不要手动改动模板 ID。自定义 ISO 目录配置和环境中的 ISO 路径均为绝对路径，移动电脑后应重新选择目录；已创建环境引用的旧 ISO 路径不会自动迁移，继续安装前需要确保原引用位置可访问。

只升级程序时，关闭全部环境和 DeskLab 后运行新版安装包或替换 EXE，保留数据目录。安装器升级和卸载不删除用户的 ISO、环境及自定义模板。整套数据备份同样应在所有环境和 DeskLab 关闭后进行。

## macOS 计划

macOS 尚未适配，当前编译目标为 Windows x64；现有 EXE 不能直接变成可运行的 `.app`。

后续 `.app` 计划把启动程序、网页和对应平台的 QEMU / 固件放入应用包，用户数据放在 `~/Library/Application Support/DeskLab/`，ISO 和磁盘仍通过界面选择或导入。安装或替换应用包不应覆盖虚拟机数据。正式支持前还需要实现 macOS 文件选择、引擎打包、签名以及对应硬件的虚拟化和客体架构适配。
