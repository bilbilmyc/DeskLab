# 网络与 SSH

## 仅支持 NAT

当前产品已暂停桥接，不提供 NAT/桥接切换，不安装 TAP、不创建或修改 Windows 网络桥。旧实验接口 `/api/network/setup` 返回 410。桥接研究保留在历史文档中，不是本版安装步骤。

每个实例使用 QEMU 用户模式 NAT，通常在客体内看到 `10.0.2.15`。这不是 VMware VMnet8 式的共享虚拟网段，也不是 Windows 可以直接 SSH 的地址；多个实例可以在各自隔离网络里使用同一个内部地址。

Windows 本机通过 `127.0.0.1:独立端口` 连接。程序从 2222 起选择 SSH 端口，优先保留原端口；如有冲突使用可用端口，请始终以“连接与网络”显示的命令为准。

```powershell
ssh -i 'D:\apps\DeskLab\data\ssh\id_ed25519' -o IdentitiesOnly=yes -p 2222 root@127.0.0.1
```

实例启动不代表 SSH 已就绪。手动安装需自行启用 SSH、允许目标用户登录并授权公钥。不要通过关闭主机指纹检查来处理连接错误。

## 密钥与账号

每个 DeskLab 数据目录维护一把 Ed25519 密钥，可授权给多台实例。私钥位于 `data/ssh/id_ed25519`，公钥为同级 `.pub`；Windows ACL 限制访问，API 不返回私钥。私钥默认无口令，拥有该 Windows 用户权限的人可使用它。

新装 Ubuntu、Debian、Rocky 的自动安装配方将公钥加入 root 的 `authorized_keys`，开启公钥认证并禁用 SSH 密码认证。控制台的自动登录和默认密码另行保留。

旧实例、导入磁盘、手动安装或来自其他数据目录的模板不一定已有本机授权。“连接与网络”提供一次性公钥授权步骤；该操作保留原来的授权，不会替旧系统统一修改密码策略。使用其他用户名时需在该用户目录中授权，root 的授权不适用于其他账号。

升级会保留密钥。备份数据目录时按凭据备份保管；删除私钥再生成新密钥不会自动更新旧实例的授权。当前没有密钥轮换向导、外部公钥导入、多用户 IAM 或云 KMS。

## 端口与局域网

“端口映射”统一展示 SSH、虚拟机 NAT 自定义映射和 Docker 发布端口。虚拟机映射可增删改，运行时可增删，修改已有规则需先关机。协议与宿主端口有唯一约束，避免资源间冲突。

新映射只绑定 `127.0.0.1`，暂不提供局域网发布开关。内置 Docker 使用宿主到专属 Linux、再到容器的两层转发，页面显示宿主可用入口。外部 Docker 的已有映射按该引擎实际绑定显示。

映射存在不表示服务一定可用，还需要客体内的服务监听目标端口。更多规则见 [Docker 与存储](docker-and-storage.md)。独立 Docker 的管理通道采用独立双向 TLS，不复用普通虚拟机的 root SSH 登录。
