# 版本与发布约定

## 当前状态

当前正式版为 `v1.0.0`，发布 Windows x64 基础包。`master` 是默认集成主线；稳定下载以 [Release](https://github.com/bilbilmyc/DeskLab/releases/latest) 的标签、源码提交和构建记录为准。

`v1.0.0-rc1` 候选分支与同名预发布标签保留，二者是独立的 Git 引用。后续候选版使用新的版本号和标签，同一分支上的修订用 commit SHA 和 Actions run 区分；不要移动已公开的标签。

首次 Git 初始化保留一个 0.3.6 基线提交于 `master`；RC 分支在该基线上切换候选版本号。后续通过评审将验证过的修改合回主线。不要为了清空 CI 历史或改版本号而强推覆盖已经分享的提交。

## RC 构建

提交到 RC 分支后，Actions 自动生成带版本名的基础构建产物。版本来自 `package.json`；Bun 和安装器使用该版本，Windows PE 文件资源只能使用对应数字部分，例如 `1.0.0`，界面/API 和安装器仍显示完整 RC 名称。

分支推送仅构建；`v*` 标签推送自动构建并发布 Release，版本必须与 `package.json` 一致。附件先进入草稿，版本与 SHA-256 全部核对后再公开。RC 标记为 Pre-release；正式版不带预发布标记，并由 GitHub 按版本决定 Latest。详见 [构建与 CI](build-and-ci.md)。

发布说明应列明对应 commit、构建 flavor、SHA256、组件清单、已验证范围及已知问题；基础构建不能标成包含独立 Docker 的完整构建。

## 正式版前需要确认

- 核心创建、ISO 错配校验、模板克隆、正常/强制关机、重启、SSH 与端口映射在目标 Windows 配置上通过。
- 重要升级路径、SQLite 迁移、备份恢复、独立引擎数据与外部容器边界完成验证。
- 完整包的可复现引擎资源、依赖来源、许可证/对应源码说明和签名分发策略明确。
- README、已知限制、变更记录与实际安装包一致；明确第一方源码许可证。
- 用户决定可以发布，再移除预发布后缀、创建相应 tag/Release。CI 绿灯是必要证据之一，不自动触发“转正”。

源码和文档更新不会自动升级本机已安装的 DeskLab。替换正在使用的程序应作为单独操作，先保存工作并确认备份与恢复范围。
